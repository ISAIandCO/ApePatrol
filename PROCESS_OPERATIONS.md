# Операции процессов

Общий интерфейс и правила работы описаны в [ApeShareCore/PROCESS_OPERATIONS.md](https://github.com/ISAIandCO/ApeShareCore/blob/feat/process-operations/PROCESS_OPERATIONS.md).

Требуется ApeShareCore 1.7+. Сначала интегрируйте PR общей библиотеки, затем PR расширения. Штатный резолвер продолжает выбирать совместимый `main`, без постоянной фиксации SHA или ветки. Для проверки ещё не интегрированных веток: `APE_CORE_SOURCE=../ApeShareCore npm run build:self-hosted`.

Настройки → «Операции процессов»: проверьте и включите нужные профили, сохраните, затем перезагрузите граф. Правый клик по процессу → категория → загрузка до 25 событий. В каталоге 15 профилей: 6 Windows Sysmon, 5 Windows Security и 4 Linux auditd. При обновлении нажмите «Добавить недостающие рекомендуемые профили», затем сохраните: существующие настройки не заменяются.

Windows Security: файлы/реестр/процессы — 4663 с отдельным ObjectType; значения реестра — 4657; разрешённые и заблокированные соединения — 5156/5157. Нужны соответствующие Audit Policy и SACL.

Linux auditd: файловые syscall, connect, ptrace/process_vm_* и finit_module. Нужны настроенный audit и нормализованное событие с pid инициатора и достоверной целью. Поле syscall должно быть декодировано с учётом ABI; отдельные PATH/SOCKADDR не связываются по PID. finit_module требует разрешённого пути по FD. DNS и .so по auditd не имитируются.

Windows Security использует object.type со значениями file / key / process; прежние нетронутые пустые шаблоны обновляются при загрузке настроек. Поле syscall без подтверждённого универсального сопоставления остаётся незаполненным: такой профиль явно помечен «требуется настройка» и не включается, пока не заполнены обязательные поля. Все профили выключены до проверки источника и маппинга. Подробные поля, требования и пределы описаны в общей документации. Проверки адаптеров используют синтетические события с явно заданным маппингом; это не подтверждение штатных нормализаторов живой SIEM.

Перед запросом операций расширение получает events_metadata: отсутствующие стандартные дополнительные поля исключаются, object.fullpath при необходимости заменяется доступными object.path + object.name. Если GUID недоступен, используется PID с предупреждением о точности. Отсутствующие обязательные или пользовательские поля дают ошибку с названием профиля до отправки POST. Ошибка чтения метаданных не скрывается и не приводит к запросу с непроверенными полями.

Выключенные и неприменимые к ОС категории отсутствуют в карточке процесса. Незавершённые профили помечены в настройках; их переключатель становится доступен после заполнения обязательных полей.

Подтверждённое сопоставление Security 4663 (ключ реестра): event_src.provider=Microsoft-Windows-Security-Auditing, event_src.title=windows, object.type=key, инициатор subject.process.id, объект object.fullpath. Прежнее значение registry_key и проверка провайдера в event_src.title исправлены. Несовпадающее значение существующего поля обычно даёт пустую выборку, а не доказывает причину HTTP 400; для диагностики отказа нужен payload запроса и ответ API.
