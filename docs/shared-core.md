# Общее ядро ApePatrol и KumApe

Оба расширения используют одинаковые файлы `src/shared/core/`. Начальная версия ядра — **1.0.0**, исходная реализация взята из ApePatrol 3.4.14. Пакеты расширений остаются самостоятельными; соседний репозиторий и сеть не нужны для сборки или работы установленного расширения.

## Что уже общее

| Модуль | Ответственность |
|---|---|
| `providers.js` | Каталог VirusTotal, AbuseIPDB, OpenTIP, ThreatFox: типы IOC, адреса, имена секретов |
| `ioc-enrichment.js` | Запросы к четырём API, аутентификация, нормализация результатов, ошибки и Retry-After |
| `ioc.js`, `ip.js`, `hash.js`, `url.js` | Нормализация значений, классификация IP, разбор хешей и URL |
| `ai-transport.js` | OpenAI-совместимый HTTP-транспорт: полный endpoint, необязательный Bearer-ключ, таймаут и отмена |
| `markdown.js` | Отображение Markdown без выполнения HTML из ответа модели |
| `event-compare.js` | Сравнение двух/трёх событий, стабильное сравнение вложенных объектов, экспорт Markdown |
| `force-layout.js`, `spatial-index.js` | Физика и пространственный индекс графа |

Старые пути импортов сохранены через короткие обёртки. Реальных вторых реализаций перечисленных алгоритмов в продуктовых модулях нет. Оба проекта выполняют одинаковые контрактные тесты `scripts/core-contracts.mjs`.

## Граница адаптера

Ядро не обращается к `browser.storage`, DOM конкретной SIEM, её REST API или настройкам продукта. HTTP-функции принимают `fetchImpl` и `AbortSignal`, что позволяет проверять их без доступа к провайдерам.

| Общий контракт | Адаптация KumApe | Адаптация ApePatrol |
|---|---|---|
| IOC `{type, value}`; тип хеша `hash` | Перевод `md5`/`sha1`/`sha256` в `hash`; поля KUMA остаются в kuma-adapter | Распознавание полей MP SIEM остаётся в shared/ioc |
| Секреты по ключам каталога | Существующий `iocApiKeys[id]` преобразуется перед вызовом | Существующие именованные секреты передаются напрямую |
| Результат `{provider, verdict, summary, details, type, value}` | Локализованное пояснение ошибок и 404 в ioc-lookup | Прямой вызов общего клиента; batch сохраняет свой формат кеша |
| `requestChatCompletion(endpoint, serialized, options)` | Настройки LAN endpoint, история, privacy и подтверждение payload | Настройки endpoint, вложения, privacy и previewHash |
| `compareEvents(events, {fieldGroup})` | Группировка полей SourceAddress, DeviceProcessID и других KUMA-полей | Группировка subject/object/src/dst и других MP SIEM-полей |

Endpoint и ключи не переписываются при обновлении. Общий транспорт отправляет API-ключ только явно указанному endpoint, не использует браузерные cookies и не следует перенаправлениям. Проверки Firefox permissions остаются в продуктовых адаптерах. Таймауты AI сохраняются разными: KumApe 120 секунд, ApePatrol 30 секунд. Дополнение базового `/v1` до `/v1/chat/completions` включается адаптером KumApe; полный путь сохраняется.

В KumApe общие ES-модули собираются esbuild в два существующих classic-script entry point: каталог IOC и background-адаптер. Остальная сборка сохранена. ApePatrol использует свою существующую сборку esbuild. Исполняемый код в рантайме из сети не загружается.

## Как менять общий функционал один раз

Работать можно в любом из репозиториев. Пока эталоном является ApePatrol.

1. Изменить нужный модуль `src/shared/core/` и общий контрактный тест в `scripts/core-contracts.mjs`.
2. Запустить `npm run test:core` и тесты продукта.
3. Зафиксировать новую версию ядра:

   ```sh
   npm run core:sync -- --record --version 1.0.1
   ```

4. Из второго репозитория перенести ядро одной командой:

   ```sh
   npm run core:sync -- --from ../ApePatrol
   ```

5. Проверить тождественность и оба продукта:

   ```sh
   npm run core:check -- --peer ../ApePatrol
   npm run test:core
   npm test
   ```

6. Поднять версии расширений, собрать их и открыть связанные PR в обоих репозиториях. PR с общей функциональностью должны содержать одну и ту же версию и хеши ядра.

`shared-core.lock.json` фиксирует версию и SHA-256 каждого модуля, команды синхронизации и контрактных тестов. CI проверяет соответствие файлов lock-файлу и выполняет общие тесты. Перенос откажется перезаписывать локальные изменения ядра, ещё не зафиксированные через `--record`. Он затрагивает только файлы из общего набора, не переносит настройки, ключи или продуктовый код.

Локальная CI-проверка подтверждает соответствие опубликованному набору хешей, но не обращается в другой репозиторий: для сравнения двух веток применяется `--peer`. Намеренное изменение lock-файла только в одном репозитории требует обычного ревью; это не защита от разработчика с правом изменения исходников.

Для нового провайдера запрос и нормализацию нужно писать один раз в ядре. Каталог используется обоими клиентами, меню и настройками KumApe, а также меню и batch ApePatrol. У ApePatrol форма настроек пока статическая: для нового ключа потребуется добавить её поля и статус. Названия старых ключей менять не следует.

## Что пока остаётся продуктовым

SQL KUMA и PDQL MP SIEM, извлечение событий из DOM, маршруты открытия карточек, нормализация процессов и типов событий, API расследования/правил/активов остаются адаптерами. Нельзя выбирать реализацию внутри ядра по имени продукта.

История AI, схемы вложений и хранилища расследований ещё различаются. В этом изменении унифицирован их транспорт и отображение Markdown, но не формат сохранённых данных. Следующий перенос этих функций должен включать явную миграцию существующих диалогов и расследований. Полное совпадение UI этим PR не заявляется.
