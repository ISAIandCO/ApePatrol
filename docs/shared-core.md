# ApeShareCore во время сборки

Общие модули находятся в [ApeShareCore](https://github.com/ISAIandCO/ApeShareCore). В дочернем репозитории хранится только совместимая major-версия: `apeShareCore.major: 1`. SHA ядра не закрепляется в package.json/package-lock.json. Отдельные PR обновления зависимости и ежедневный workflow их создания удалены.

Обычные команды тестов и сборки автоматически выбирают последнюю совместимую ревизию из first-parent истории `main` ApeShareCore. Это включает исправления без изменения версии пакета. Если main уже содержит 2.x, потребитель 1.x продолжает собираться с последней совместимой ревизией 1.x; новый major подключается явно. Сетевые ошибки не маскируются старым кешем.

Выбранный архив устанавливается только в node_modules, с `--no-save --package-lock=false --ignore-scripts`. Репозиторные manifest/lock и версия расширения не меняются. Локальный файл `.apesharecore.json` игнорируется Git и фиксирует выбор текущей сборки. `npm ci` устанавливает инструменты из lock-файла; первая команда сборки или тестирования затем подготавливает ядро.

Все этапы одного запуска используют один SHA: ядро не может обновиться между тестами и упаковкой. CI выбирает его один раз перед тестами. В каждый артефакт входит `apesharecore-build.json` с версией, SHA и checksum. Это журнал происхождения сборки, а не фиксация зависимости в репозитории. Воспроизводимость проверяется на одной выбранной ревизии.

Для повторной сборки:

```sh
APE_CORE_SHA=<sha-из-apesharecore-build.json> npm run build:self-hosted
```

Без переменной следующая сборка снова проверит актуальную совместимую ревизию. Уже установленные расширения получают новый код ядра только с обновлением самого расширения; загрузки исполняемого кода из GitHub в рантайме нет.

## Проверки и разработка

```sh
npm ci
npm run test:core
npm test
```

`core:prepare` подготавливает ядро отдельно. `core:check` проверяет установленную ревизию и метаданные; `node scripts/check-core.mjs --built` также сверяет метаданные артефакта и отсутствие bare package imports.

Для проверки ещё не опубликованных изменений библиотеки:

```sh
APE_CORE_SOURCE=/path/to/ApeShareCore npm run build:self-hosted
```

Этот режим пакует кандидат без lifecycle scripts и помечает источник в метаданных как candidate. Он применяется workflow Consumer compatibility в ApeShareCore: библиотека проверяется тестами и сборками подключённых расширений до принятия изменений.

Общие API и их эффекты описаны в [CONTRACTS.md](https://github.com/ISAIandCO/ApeShareCore/blob/main/CONTRACTS.md). SIEM DOM/API, SQL/PDQL, ключи, разрешения, persistence и поля событий остаются адаптерами расширений. Форматы сохранённых данных не меняются.
