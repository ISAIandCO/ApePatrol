<p align="center">
  <b>Firefox-компаньон для MaxPatrol SIEM</b>
</p>

**ApePatrol** — расширение для Firefox, которое добавляет в **MaxPatrol SIEM** инструменты, полезные в повседневном расследовании: граф процессов, связанные события, IOC-проверки, рабочее пространство расследования, сравнение событий и AI-ассистента.

Проект основан на **[SiemMonkey](https://github.com/Security-Experts-Community/siem-monkey)**, но был практически полностью переработан под Firefox.

Основная версия, на которой идёт разработка и проверка — **MaxPatrol SIEM 27.3**. Жёсткой проверки версии нет: если интерфейс SIEM немного отличается, ApePatrol старается определить доступные возможности сам и продолжить работу там, где это возможно.

> [!NOTE]
> ApePatrol — независимый open-source проект. Он не связан с Positive Technologies и не является официальным компонентом MaxPatrol SIEM.

## Что есть в ApePatrol

### События

В карточке события появляются дополнительные действия, чтобы не таскать данные между вкладками вручную.

Можно:

* скопировать или скачать JSON события;
* получить ссылку на событие;
* добавить событие в расследование;
* найти связанные события по хосту, учётной записи, IP, GUID процесса, хешу или исполняемому файлу;
* запустить IOC-проверку прямо из нужного поля;
* увидеть связанный `incident_id`, если он есть.

Если у самого SIEM уже есть штатное меню действий для поля, ApePatrol старается не дублировать его своим.

---

### Граф процессов

Для **Sysmon Event ID 1**, **Windows Event ID 4688** и Linux `execve` можно построить интерактивный граф процессов.

Есть три режима:

* **Связи** — обычный граф родительских и дочерних процессов;
* **По времени** — тот же процессный контекст с привязкой ко времени;
* **Пошаговый** — начинаем с интересующего процесса и вручную расширяем нужные ветки.

Первые два режима полезны на малых промежутках для общего понимания контекста, последний - на больших выборках, чтобы вместо вываливания на экран тысячи процессов идти по цепочке постепенно.

<details>
<summary><b>Что ещё умеет граф</b></summary>

<br>

* искать родителей и дочерние процессы;
* догружать цепочку прямо из карточки узла;
* фильтровать события по содержимому;
* использовать регулярные выражения;
* ограничивать диапазон по времени;
* отменять построение;
* убирать дубли;
* менять лимит числа процессов;
* догружать данные постранично;
* сохранять состояние графа в рамках сессии;
* переподключаться к другой вкладке того же SIEM.

Для раскладки используется ускоренный компонентно-иерархический подход, чтобы крупные графы быстрее приходили в читаемый вид.

</details>

---

### IOC-проверки

IP, домены, хеши и другие IOC можно проверять прямо из события.

Через API интегрированы:

* **VirusTotal**;
* **AbuseIPDB**;
* **Kaspersky OpenTIP**;
* **ThreatFox**.

Для сервисов, где полноценная API-интеграция не нужна или неуместна, есть быстрые переходы к готовым отчётам — например Shodan, GreyNoise, MalwareBazaar и URLhaus.

<details>
<summary><b>Пакетная проверка IOC</b></summary>

<br>

Если индикаторов много, их можно отправить на проверку пакетом.

Перед запуском показывается preview, а результаты разных провайдеров обрабатываются независимо друг от друга: ошибка одного сервиса не ломает всю проверку.

Есть:

* ограничение параллельных запросов;
* backoff;
* нормальная обработка HTTP `429`;
* повторный запуск отдельного провайдера;
* отмена операции;
* локальный TTL-кэш результатов.

API-ключи в кэш не попадают.

</details>

---

### Рабочее пространство расследования

Чтобы расследование не превращалось в набор открытых вкладок и текстовый файл с заметками, в ApePatrol есть локальный **Investigation Workspace**.

Туда можно складывать:

* события;
* процессы;
* IOC;
* хосты;
* учётные записи;
* ссылки на инциденты;
* заметки;
* теги.

События в расследовании подписаны по содержимому и по умолчанию расположены по времени, поэтому цепочку действий можно читать без постоянного раскрытия JSON.

В карточке расследования строится динамический локальный граф **«событие ↔ сущность»**. Он объединяет одинаковые хосты, учётные записи, SID, IP-адреса, процессы, файлы, хэши, домены, сессии и инциденты независимо от того, выступают они в событии как `subject`, `object`, `src` или `dst`. Узлы можно перемещать, а свёрнутая по умолчанию панель позволяет настроить силы связей.

Из выбранных на графе сущностей можно собрать безопасный фильтр `AND`/`OR`, найти связанные события в SIEM в заданном диапазоне и явно добавить нужные результаты в расследование.

Также есть поиск и сортировка расследований, а готовое расследование можно выгрузить в **JSON** или **Markdown**.

Данные хранятся локально в IndexedDB.

---

### Сравнение событий

Два или три сохранённых события можно сравнить между собой.

ApePatrol отдельно показывает различия в:

* процессах;
* сетевых данных;
* учётных записях;
* хостах;
* правилах;
* исходном событии.

Получившийся diff можно скопировать в JSON или Markdown.

---

### SEC AI Assistant

В расширение встроен AI-ассистент, рассчитанный именно на работу в ходе расследования.

В пределах одной вкладки SIEM ведётся один диалог. В него можно по мере работы прикладывать дополнительные события, а при необходимости перенести разговор в Investigation Workspace и продолжить уже в контексте всего расследования.

Ответы с Markdown отображаются нормально, для подключения используется OpenAI-compatible API.

<details>
<summary><b>Что именно уходит в AI</b></summary>

<br>

Перед отправкой запроса можно посмотреть его итоговое содержимое:

* какие поля события попадут в запрос;
* какой текст будет отправлен;
* реальный размер payload в UTF-8;
* какой режим приватности используется;
* какие локальные предупреждения сработали.

Есть три режима передачи данных:

* **строгий список полей** (`strict allowlist`);
* **с маскированием** (`redacted`);
* **полные данные** (`full`).

После preview содержимое запроса не должно незаметно измениться перед отправкой.

</details>

<details>
<summary><b>Доступ AI к SIEM</b></summary>

<br>

AI может запросить дополнительный контекст из текущей вкладки, но только через заранее определённые read-only операции и после подтверждения пользователя.

Например:

* связанные события;
* процессы;
* данные об активе / EDR;
* информацию о правиле корреляции;
* выбранные объекты из Investigation Workspace.

Произвольных URL, произвольного PDQL и операций изменения данных у AI нет.

</details>

---

### Правила корреляции

Для правила корреляции ApePatrol может собрать в одном месте дополнительную информацию:

* метаданные;
* материалы базы знаний;
* ссылки;
* MITRE ATT&CK mappings.

Сопоставления с MITRE ATT&CK берутся только из данных SIEM. Расширение не пытается самостоятельно придумать подходящую технику по названию события.

---

### PDQL-фильтры

В комплекте есть **48 готовых русскоязычных PDQL-фильтров** с описаниями.

Перед применением ApePatrol проверяет, есть ли в текущем контексте необходимые для фильтра поля.

---

### Табличные списки

С Table Lists можно работать прямо из расширения:

* смотреть содержимое;
* добавлять значения;
* удалять значения.

Перед изменением показывается preview и требуется явное подтверждение.

---

### Корпоративные профили

Настройки ApePatrol можно переносить и централизованно задавать через профили.

Есть импорт/экспорт с версионированием, объединение или полная замена настроек, валидация и поддержка Firefox `storage.managed`.

Администратор может задавать значения по умолчанию и блокировать отдельные параметры.

Секреты в экспортируемые профили не попадают.

<details>
<summary><b>Прочие возможности</b></summary>

<br>

Кроме основного функционала, в расширении есть:

* опциональное описание IOC через отдельную подтверждаемую операцию SIEM;
* скрытие EDR-элементов интерфейса без блокировки XHR/fetch;
* применение изменённых настроек к уже открытым вкладкам;
* feature toggles;
* пользовательские aliases и фильтры;
* настройка IOC-провайдеров;
* управление лимитами графа процессов.

</details>

## Совместимость

| Компонент                    | Поддержка                                                |
| ---------------------------- | -------------------------------------------------------- |
| Firefox                      | **Desktop 140+**                                         |
| MaxPatrol SIEM               | **27.3 — основная версия для разработки и тестирования** |
| Другие версии MaxPatrol SIEM | Best effort                                              |

Версия SIEM сама по себе не является причиной для блокировки расширения.

Если нужные элементы интерфейса и API на месте, ApePatrol постарается с ними работать. Но гарантировать совместимость со всеми версиями MaxPatrol SIEM, разумеется, нельзя.

## Установка и доступ к SIEM

После установки ApePatrol **не получает доступ ко всем сайтам**.

Адрес SIEM добавляется вручную, например:

```text
https://siem.example.internal
```

После этого Firefox попросит разрешение только для этого адреса:

```text
https://siem.example.internal/*
```

Если адрес удалить из настроек или отозвать разрешение Firefox, ApePatrol перестанет работать с этим SIEM.

<details>
<summary><b>Приватность и безопасность</b></summary>

<br>

ApePatrol старается не получать больше прав, чем ему действительно нужно.

### API-ключи и секреты

Секреты хранятся только в `storage.local`.

Они не передаются в контекст страницы, не записываются в DOM и не должны попадать в журнал.

### Работа со страницей SIEM

Расширение работает в Firefox `ISOLATED` world и не патчит сетевой runtime MaxPatrol SIEM.

Перехвата `fetch` и XHR страницы нет.

### Операции, которые меняют данные

Изменение Table Lists и другие mutating-операции вынесены в отдельные типизированные background actions.

Перед выполнением ещё раз проверяются origin, состояние функции, token и изменяемые данные.

### Недоверенные данные

Данные событий, ответы внешних сервисов, вывод LLM и пользовательские настройки считаются недоверенными.

Для их отображения используются безопасные DOM API и `textContent`.

### Внешние сервисы

Передача данных наружу по умолчанию выключена.

Чтобы ApePatrol отправил что-либо во внешний API, должны одновременно быть:

1. включена соответствующая интеграция;
2. выдано разрешение Firefox на передачу данных;
3. разрешён конкретный API endpoint;
4. выполнено явное действие пользователя.

</details>
